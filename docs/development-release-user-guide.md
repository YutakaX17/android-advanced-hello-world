# Development release user guide

The development release is a non-production, minified Android build for testing the
complete application against an Advanced Hello World backend running on a developer PC.
It is not suitable for Google Play or production distribution.

## What the development release contains

- Application ID `io.github.yutakax17.advancedhelloworld.development`, so it can coexist
  with the production application.
- Version suffix `-development`.
- Release-style shrinking and obfuscation.
- APK and AAB artifacts signed with the disposable Android debug key generated by CI.
- API base URL `http://127.0.0.1:8000` for use with an ADB reverse connection.
- Cleartext HTTP enabled only in the development variant.

The Maven/GPG key used to sign library publications does not sign these Android artifacts.
The future production APK and AAB require a separate, long-lived Android keystore.

## Start the backend on the PC

Use the assembled Advanced Hello World backend family. Start PostgreSQL, apply Django
migrations, and run the backend on port 8000 with the core and messages modules installed.
The server must expose its health and message APIs, including:

```text
http://127.0.0.1:8000/api/v1/health/live
http://127.0.0.1:8000/api/v1/messages
```

Confirm the health endpoint from the PC before connecting a device:

```shell
curl --fail http://127.0.0.1:8000/api/v1/health/live
```

## Connect a physical Android phone over USB

1. Enable Developer options and USB debugging on the phone.
2. Connect the phone and accept its debugging authorization prompt.
3. Confirm that ADB can see it and create the port bridge:

   ```shell
   adb devices
   adb reverse tcp:8000 tcp:8000
   adb reverse --list
   ```

4. Install the downloaded development APK:

   ```shell
   adb install -r app-development.apk
   ```

The application connects to `127.0.0.1:8000`; ADB forwards that device-side address to
port 8000 on the PC. Recreate the reverse rule after reconnecting the phone or restarting
ADB. Remove it when testing is complete:

```shell
adb reverse --remove tcp:8000
```

## Test on an emulator

Use the same reverse bridge before installing the APK:

```shell
adb reverse tcp:8000 tcp:8000
adb install -r app-development.apk
```

The ordinary debug build still defaults to `http://10.0.2.2:8000`; the tagged development
release deliberately uses the ADB-reversed loopback endpoint so that one artifact works on
both an emulator and a USB-connected phone.

## Test the AAB

An AAB cannot be installed directly. Download the integrity-pinned Bundletool release,
then generate and install device APKs while the phone is connected:

```shell
java -jar bundletool-all-1.18.3.jar build-apks \
  --bundle=app-development.aab \
  --output=app-development.apks \
  --mode=universal
java -jar bundletool-all-1.18.3.jar install-apks \
  --apks=app-development.apks
```

Validate the bundle independently when required:

```shell
java -jar bundletool-all-1.18.3.jar validate \
  --bundle=app-development.aab
```

## Development release process

1. Merge an approved change after CI, Security, and Integration pass on the exact head.
2. Create `dev-v<distributionVersion>` from the reviewed `main` commit. For version 0.2.0,
   the tag is `dev-v0.2.0`.
3. The Development release workflow reruns backend/device integration, builds and verifies
   the APK and AAB, validates the AAB, and produces checksums, an SBOM, component metadata,
   and provenance.
4. GitHub publishes the result as a prerelease.

Do not reuse a development tag. Increment the distribution version before publishing a
replacement development release.

## Required verification journey

- Create a message while offline and restart the application.
- Confirm that the message remains locally visible after restart.
- Restore connectivity and synchronize.
- Confirm that the backend receives the message once with the same idempotency identity.
- Create a message through the backend and refresh the application.
- Confirm that the backend-originated message is stored and displayed locally.
- Disconnect and reconnect the USB cable, restore `adb reverse`, and verify recovery.

## Troubleshooting

- `connection refused`: verify the backend health endpoint and recreate `adb reverse`.
- `unauthorized device`: unlock the phone and accept the USB debugging prompt.
- multiple devices: pass `-s <serial>` to each `adb` command.
- installation conflict: uninstall the development application or use `adb install -r`.
- data from an older build affects testing: clear
  `io.github.yutakax17.advancedhelloworld.development` in Android settings or with ADB.

Never place credentials in the API URL or commit signing files, passwords, tokens, or
backend secrets to this repository.
